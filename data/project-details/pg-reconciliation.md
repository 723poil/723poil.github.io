## 🧾 요약

샵체인의 결제 플랫폼 정산 개발을 담당하며, 결제 내역 조회 지연과 PG사 결제 내역 수기 대조 문제를 개선했습니다.

실시간 결제 처리 데이터와 정산 검증용 데이터를 분리하고, PG사 파일 업로드 기반의 자동 대조 기능을 구현해 운영 담당자의 검증 시간을 줄이고 정산 처리 안정성을 높였습니다.

## 🔍 문제

정산 기간의 결제 내역을 조회할 때 실제 결제 테이블을 직접 조회하고 있어, 데이터량이 많을 경우 응답 시간이 30초에서 60초 이상 걸리거나 조회가 실패하는 경우가 있었습니다.

또한 내부 결제 내역과 PG사 결제 내역을 엑셀로 직접 대조하고 있어, 운영 담당자가 불일치 건을 수작업으로 확인해야 했습니다. 실시간 결제 처리와 정산 검증 조회가 같은 데이터 흐름에 묶여 있어, 운영성 개선을 위해 책임 분리가 필요했습니다.

## 🛠️ 개선 과정

먼저 운영 담당자와 미팅을 진행해 실제 정산 검증 흐름과 지연이 발생하는 구간을 확인했습니다. 이후 NestJS Scheduler를 활용한 배치 프로세스로 매일 정산용 데이터를 별도 적재하도록 구성하고, 정산 도메인에서는 해당 데이터를 기준으로 조회하도록 변경했습니다.

Vue3 기반 관리 콘솔에서는 PG사 결제 내역 파일을 업로드할 수 있도록 했고, NestJS 서버에서 내부 결제 내역과 PG사 결제 내역을 1:1로 대조하도록 구현했습니다. 운영 담당자는 엑셀을 직접 비교하는 대신 최종 검증 결과와 불일치 건만 확인할 수 있게 되었습니다.

## 📈 성과

최대 60초 이상 소요되거나 실패하던 결제 내역 조회를 10초 이내에 안정적으로 처리할 수 있게 개선했습니다.

최소 1시간에서 길게는 하루 종일 걸리던 검증 작업은 30분 이내로 단축되었고, 운영 담당자는 엑셀 수기 대조 대신 시스템의 검증 결과를 기준으로 정산 데이터를 확인할 수 있게 되었습니다.

## 🌱 회고

운영 담당자의 반복 업무를 줄이고 정산 검증 흐름을 개선했다는 점에서 의미 있는 경험이었습니다. 좋은 개선은 기술 적용 자체보다 현업의 업무 흐름과 실제 불편을 정확히 이해하는 데서 시작된다는 점을 배웠습니다.

다만 추가 인덱스 적용과 같은 성능 튜닝은 팀 내부적으로 보수적인 판단이 필요해 더 깊게 시도하지 못한 점이 아쉬웠습니다. 또한 PG 결제 내역 검증 과정이 여전히 엑셀 파일 다운로드와 업로드에 의존하고 있어, 운영 편의성 측면에서는 개선 여지가 남아 있다고 느꼈습니다.

추후에는 PG사 API 연동을 통해 결제 내역을 자동으로 수집하고, 시스템 안에서 검증까지 이어지는 구조로 발전시켜보고 싶습니다.
