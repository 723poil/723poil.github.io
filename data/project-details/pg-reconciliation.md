## 요약

샵체인의 결제 플랫폼 정산 개발을 담당하며, 결제 내역 조회 지연과 PG사 결제 내역 수기 대조 문제를 개선했습니다.

실시간 결제 처리 데이터와 정산 검증용 데이터를 분리하고, PG사 파일 업로드 기반의 자동 대조 기능을 구현해 운영 담당자의 검증 시간을 줄이고 정산 처리 안정성을 높였습니다.

## 배경

정산 개발 담당자로 근무하던 중 운영 담당자로부터 결제 내역 검증과 정산 처리 과정에 시간이 오래 걸리고 불편하다는 피드백을 받았습니다.

업무를 맡은 지 얼마 되지 않아 전체 정산 프로세스를 충분히 이해한 상태는 아니었기 때문에, 먼저 운영 담당자와 미팅을 진행해 실제 업무 흐름과 지연이 발생하는 구간을 확인했습니다.

## 문제 분석

- 정산 기간의 결제 내역을 조회할 때 실제 결제 테이블을 직접 조회하고 있었습니다.
- 데이터량이 많을 경우 응답 시간이 30초에서 60초 이상 걸리거나 조회가 실패하는 경우가 있었습니다.
- 내부 결제 내역과 PG사 결제 내역을 엑셀로 직접 대조하고 있어, 운영 담당자가 불일치 건을 수작업으로 확인해야 했습니다.
- 실시간 결제 처리와 정산 검증 조회가 같은 데이터 흐름에 묶여 있어, 운영성 개선을 위해 책임 분리가 필요했습니다.

## 개선 과정

실시간 결제 처리 데이터와 정산 검증용 데이터의 책임을 분리했습니다. NestJS Scheduler를 활용한 배치 프로세스로 매일 정산용 데이터를 별도 적재하도록 구성했고, 정산 도메인에서는 해당 데이터를 기준으로 조회하도록 변경했습니다.

또한 Vue3 기반 관리 콘솔에서 PG사 결제 내역 파일을 업로드하면, NestJS 서버가 내부 결제 내역과 PG사 결제 내역을 1:1로 대조하도록 구현했습니다. 운영 담당자는 엑셀을 직접 비교하는 대신 최종 검증 결과와 불일치 건만 확인할 수 있게 되었습니다.

## 트러블슈팅과 의사결정

처음에는 조회 성능만 개선하면 된다고 생각할 수 있었지만, 실제 문제는 단순한 쿼리 속도보다 정산 검증 업무가 실시간 결제 데이터에 직접 의존하고 있다는 점에 있었습니다.

그래서 결제 처리 테이블을 계속 직접 조회하는 방식 대신, 정산 검증 목적에 맞는 별도 데이터를 구성하는 방향을 선택했습니다. 이 방식은 실시간 결제 처리 흐름에 주는 영향을 줄이면서도 운영 담당자가 필요한 기간별 정산 데이터를 더 안정적으로 조회할 수 있게 했습니다.

PG사 결제 내역 대조 역시 화면에 데이터를 많이 보여주는 방식보다, 서버에서 내부 결제 내역과 외부 파일을 먼저 대조하고 운영자는 결과를 확인하는 흐름으로 정리했습니다. 이를 통해 검증 업무의 기준을 사람의 수작업이 아니라 시스템의 비교 결과로 옮길 수 있었습니다.

## 성과

- 최대 60초 이상 소요되거나 실패하던 결제 내역 조회를 10초 이내에 안정적으로 처리했습니다.
- 최소 1시간에서 길게는 하루 종일 걸리던 검증 작업을 30분 이내로 단축했습니다.
- 운영 담당자가 엑셀 수기 대조 대신 최종 검증 결과와 불일치 건 중심으로 업무를 볼 수 있게 개선했습니다.

## 배운 점

이 경험을 통해 좋은 개선은 기술 적용 자체보다 현업의 업무 흐름과 불편을 정확히 이해하는 데서 시작된다는 점을 배웠습니다.

정산처럼 돈과 직접 연결되는 도메인에서는 빠르게 만드는 것만큼이나, 데이터의 책임을 명확히 나누고 운영자가 신뢰할 수 있는 검증 흐름을 만드는 것이 중요하다는 점도 체감했습니다.
