## 🧾 요약

외부 배달 주문 통합 채널앱에서 수신한 주문을 샵체인 POS의 주문·매출 흐름으로 연결하는 연동 작업을 담당했습니다.

POS 앱에서 내부 브로드캐스트로 전달되는 주문 정보를 구분해 서버로 전송하고, 서버에서는 주문 상품명을 기준으로 내부 상품코드를 매칭하는 흐름을 구현했습니다.

## 🔍 문제

외부 배달 주문은 POS 앱 위에 플로팅앱 형태로 실행되는 외부 배달 주문 통합 채널앱에서 수신하고 처리되는 구조였습니다. 해당 채널앱에서 주문을 처리하면 내부 브로드캐스트를 통해 POS 앱으로 주문 정보가 전달되었고, POS 앱은 이 데이터를 받아 서버로 넘겨야 했습니다.

가장 큰 제약은 채널앱이 샵체인의 내부 주문코드나 상품코드를 함께 전달하는 기능을 지원하지 않는다는 점이었습니다. 서버에서는 오로지 주문 상품명을 기준으로 매장의 상품을 찾아 내부 상품코드와 연결해야 했기 때문에, 상품명 매칭과 예외 처리 흐름이 중요했습니다.

## 🛠️ 개선 과정

Java Android POS 앱에서는 내부 브로드캐스트로 들어오는 데이터를 수신하고, 주문 이벤트인지 구분한 뒤 서버로 전달하는 흐름을 구현했습니다. POS 앱이 직접 생성한 주문과 외부 채널앱에서 전달된 주문을 구분할 수 있도록 데이터 처리 흐름을 정리했습니다.

PHP 서버에서는 POS 앱이 전달한 주문 상품명을 기준으로 매장 상품을 조회하고, 내부 상품코드와 연결하는 매칭 흐름을 구현했습니다. 상품명만으로 매칭해야 하는 제약이 있었기 때문에, 서버에서 상품 조회와 주문 데이터 변환을 처리한 뒤 기존 POS 주문·매출 구조에 맞게 저장되도록 구성했습니다.

테스트 매장에서는 실제 외부 배달 주문이 채널앱, POS 앱 브로드캐스트 수신, 서버 전달, 상품코드 매칭, POS 주문 반영까지 이어지는지 확인했습니다.

## 📈 성과

외부 배달 주문 통합 채널앱에서 처리된 주문을 POS 앱과 서버를 거쳐 샵체인 주문·매출 데이터로 연결할 수 있게 했습니다.

내부 상품코드를 직접 받을 수 없는 제약 안에서도 상품명 기반 매칭 흐름을 구성해, 외부 주문을 기존 매장 운영 흐름에 통합할 수 있는 기반을 만들었습니다.
