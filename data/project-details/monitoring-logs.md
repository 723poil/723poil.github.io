## 풀고 싶었던 문제

장애가 났을 때 서버 상태와 로그를 여러 위치에서 따로 확인해야 해서 원인 탐색에 시간이 오래 걸렸습니다.

## 접근 방식

서버 메트릭과 애플리케이션 로그를 한 화면에서 확인할 수 있도록 모니터링과 로그 조회 환경을 묶었습니다.

## 구현한 것

- Grafana와 Prometheus 기반 서버 메트릭 대시보드를 구성했습니다.
- NestJS 서비스 상태를 운영자가 확인하기 쉬운 지표로 정리했습니다.
- 장애 상황에서 필요한 로그 탐색 흐름을 단순화했습니다.

## 달라진 점

로그 탐색 시간이 20분 내외에서 5분 내외로 줄어들어 장애 대응 초반의 확인 비용을 낮췄습니다.
