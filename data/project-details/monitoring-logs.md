## 🧾 요약

샵체인 서비스 운영 중 서버 상태와 로그를 더 빠르게 확인할 수 있도록 모니터링 및 로그 조회 환경을 구축했습니다.

Grafana, Prometheus, Loki 기반으로 서버 메트릭과 운영 로그를 함께 확인할 수 있는 흐름을 구성하고, 장애 상황에서 필요한 로그 탐색 과정을 줄여 초기 원인 파악 시간을 단축했습니다.

## 🔍 문제

장애가 발생했을 때 서버 상태와 애플리케이션 로그를 여러 위치에서 따로 확인해야 했습니다. 이로 인해 CPU, 메모리, 요청 상태 같은 기본 지표와 실제 오류 로그를 연결해 보는 데 시간이 오래 걸렸습니다.

장애 초반에 어떤 서버에서 문제가 발생했는지 빠르게 확인하기 어려웠고, 운영 로그를 찾기 위해 여러 경로를 오가야 해 로그 탐색에 20분 내외가 걸리는 경우도 있었습니다.

## 🛠️ 개선 과정

Grafana와 Prometheus를 활용해 서버 메트릭을 한 화면에서 확인할 수 있는 대시보드를 구성했습니다. 운영 중 필요한 지표를 중심으로 화면을 정리해 장애 상황에서 먼저 확인해야 할 정보를 줄였습니다.

Loki를 통해 NestJS 서비스의 운영 로그를 조회할 수 있도록 구성했습니다. 서버 메트릭을 확인한 뒤 관련 로그로 이어질 수 있도록 탐색 경로를 단순화해, 장애 초반의 확인 과정을 줄였습니다.

## 📈 성과

장애 상황에서 서버 상태와 운영 로그를 확인하는 흐름이 단순해졌고, 원인 탐색에 드는 시간을 줄일 수 있었습니다.

로그 탐색 시간은 약 20분 내외에서 5분 내외로 줄어, 장애 대응 초반의 확인 비용을 낮췄습니다.

## 🌱 회고

운영 모니터링의 전체 흐름을 파악하고, 실제 서비스에서 메트릭과 로그를 확인하는 환경을 구성해봤다는 점에서 의미 있는 경험이었습니다.

현재 구성은 서버 상태와 운영 로그 확인에 집중되어 있었지만, 이후에는 OpenTelemetry를 활용해 단일 표준으로 관측 데이터를 수집하고, Tempo를 통해 요청 흐름별 병목 구간을 추적할 수 있는 구조를 도입해보고 싶습니다.

또한 ClickHouse와 같은 분석 기반 저장소를 활용해 관측 데이터를 더 세밀하게 분석하고, 장애 대응뿐 아니라 성능 개선에도 활용할 수 있는 모니터링 환경으로 발전시켜보고 싶습니다.
