## 풀고 싶었던 문제

PG 승인 요청이 중복되거나 승인 이후 내부 처리에 실패하면 결제 데이터 불일치가 생길 수 있었습니다.

## 접근 방식

단건 결제와 정기구독 결제 흐름을 분리하고, 주문 단위 멱등키와 Redis Lock으로 중복 처리를 제어했습니다.

## 구현한 것

- PG 승인, 내부 주문 처리, 실패 보상 단계를 분리했습니다.
- 동일 주문에 대한 중복 승인 요청을 Redis Lock으로 제어했습니다.
- 내부 처리 실패 시 PG 취소 API를 호출하도록 보상 흐름을 구성했습니다.

## 달라진 점

중복 결제와 결제 데이터 불일치 가능성을 줄이고 결제 실패 상황을 보상 처리할 수 있는 기반을 만들었습니다.
